# X85 web port — intentional behaviour changes

Every intentional deviation from the original `X85-devcore 2/` behaviour is listed here (decision D3 of the
port design). Everything else is a faithful translation.

| Id | Description | Original | Before (original) | After (port) |
|---|---|---|---|---|
| F1 | Player energy and bombs | `funcoes_J.cpp:99,102` | `energia = 10000`, `n_bombas = 50` (debug values: the ship is near-invincible, the energy bar overflows off-screen, only 5 of the 50 bomb icons fit) | `energia = 100`, `n_bombas = 5` (the June-2010 devcore values; the bar maths `*586/100` and the 5-icon layout assume them). Test: `tests/sim/jogador.test.ts` "player starts with 100 energy and 5 bombs (F1)" |
| F2 | Enemy shots never expire | `funcoes_J.cpp:259` | The expiry test is `... && tipo < BOMBA1`, so `TIROINI1..3` stay in the shared 300-slot pool forever once off-screen; in long fights the pool fills up and the player's gun stops firing (this also covers F16) | An enemy shot (`tipo > BOMBA1`) becomes `INVALIDO` when `y > 700 \|\| y < -100 \|\| x < -100 \|\| x > 900`, checked before movement like the player-shot expiry. Tests: `tests/sim/jogador.test.ts` "enemy shots leave the pool once off-screen (F2)", "enemy shots expire off every edge ... (F2)", "a full pool of stale enemy shots drains, so the player can fire again (F2/F16)" |
| F3 | INIMIGO3 kill is worth 0 | `funcoes_J.cpp:489` (binary: `addl $0x640,0x20(%ebp)`) | `score+=400;` adds 400 to the `int *score` **pointer** instead of the score, so the kill awards nothing (and later kills in that frame write past `temp_pts`) | `score.v += 400`. Tests: `tests/sim/inimigos.test.ts` "INIMIGO3 kill scores 400 (F3)", "kill scores per type match funcoes_J.cpp ..." |
| F4 | Record insert with a score below all 7 records | `funcoes_M.cpp:165-201` | The loop finds no slot; `fwrite`/`fclose` then run on the read handle that was already closed (use-after-free, double `fclose`, probable glibc abort) — reachable when a low-scoring player wins a phase | Nothing is inserted and nothing is written; the board is unchanged |
| F5 | Record insert clobbers the caller's name | `funcoes_M.cpp:190-194` | `strcpy(tempnome, tempnome2)` writes the displaced names into the caller's buffer (`saveAtual.nome`); masked only by the following `menu_saves_loadslot` | The name is copied locally (`tempnome.slice(0, 14)`); the caller's string / `saveAtual.nome` is never touched |
| F6 | One record per player name | `funcoes_M.cpp:178-198`, `jogo.cpp:213-215` | Every phase win inserts the cumulative total again, so one player fills the board with copies of their own name | If a record with exactly the same `nome` (case-sensitive) exists, it is replaced only when the new score is higher (re-inserted at its sorted position, ties above), otherwise nothing changes; a new name inserts as before |
| F7 | INIMIGO4 contact does nothing | `funcoes_J.cpp:781` | `case INIMIGO4: break;` — the enemy passes through the ship harmlessly and survives | Same as the INIMIGO3 contact branch (`funcoes_J.cpp:777-780`): `jogador.energia -= 40; marca.energia -= 9999`, so the next AI update destroys it (explosion, +500 like any ram kill). Test: `tests/sim/inimigos.test.ts` "INIMIGO4 contact damages the player (F7)" |
| F8 | Enemy shots need an active mark to hit the player | `funcoes_J.cpp:700,743` | The enemy-shot vs player test is an `else if` inside the marks loop, behind `marcas[j].tipo != INVALIDO && marcas[j].ativo`; with no active mark (lulls between waves) enemy bullets pass through the ship | The test runs once per shot, before the marks loop, independent of the marks. With at least one active mark the outcome is the original one (energy changes commute; the player's death is decided later, in `jogo_atualiza_jogador`). Tests: `tests/sim/inimigos.test.ts` "enemy shot hits player with no active enemies (F8)", "an enemy shot damages the player once, also with many active marks" |
| F9 | TIRO3–TIRO6 hitbox offset from the visual | `funcoes_J.cpp:704` vs `jogo.cpp:308-315` | Collision tests the shot's native mask (30×30, 30×30, 80×80, 15×30) with its top-left at `(x, y)`, but the shot is drawn scaled to t×t (TIRO6: t×2t) at `(x - t/2, y)`, so the hit area sits right of and below the drawn shot | The native mask is tested with its centre on the drawn quad's centre: top-left `(x - t/2 + (dw - W)/2, y + (dh - H)/2)` with C integer division (`posicao_colisao_tiro` in `funcoes_J.ts`). TIRO1/TIRO2/BOMBA1/enemy shots are drawn at native size at `(x, y)` and are unchanged. Tests: `tests/sim/inimigos.test.ts` "TIRO3 … TIRO6 hits where it is drawn: native mask centred on the drawn quad (F9)" |
| F10 | Orbits jump when `angulo` reaches 360 | `funcoes_J.cpp:438,502,552,579,606,637` | `if (angulo < 360) angulo += 0.08f; else angulo = 0;` — 360 rad is not a multiple of 2π, so INIMIGO1/INIMIGO4/BOSS1–4 orbits jump visibly after ~56 s | Below 360 the float accumulation is bit-identical; the reset becomes `angulo = fround(fround(angulo + 0.08f) % 2π)`, so the orbit continues smoothly and keeps advancing. Test: `tests/sim/inimigos.test.ts` "orbits stay continuous when angulo passes 360 (F10)" |
| F11 | Weapon cycle reads `tiro_liberado[-1]` | `jogo.cpp:230-234` | `do { if (tiro_atual-- < 1) tiro_atual = 6; } while (!saveAtual.tiro_liberado[tiro_atual-1]);` — going down from weapon 1 it tests index −1 (the last byte of `planeta_atual`, always 0) before wrapping to 6; with nothing unlocked it would loop forever | `jogo_troca_tiro` (`web/src/game/jogo.ts`): decrement, wrap below 1 to 6, stop at the first unlocked weapon — same results, no index −1 read, at most 6 steps (with nothing unlocked the weapon is unchanged). Test: `tests/sim/partida.test.ts` "weapon cycle: previous unlocked weapon, wraps to the highest, never reads index -1 (F11)" |
| F12 | Ready screen drawn once onto the back buffer | `jogo.cpp:116-123` | `ready.png` is drawn once without a clear, then the loop only swaps buffers: page-flip drivers alternate [loading] / [stale buffer + ready] (flicker) | Every frame of the wait clears and draws `loading.jpg` at (0,0) and `ready.png` at (180,440) (the intended composite). A left click / tap also dismisses it (touch devices have no Space); Esc still does nothing there. Test: "loading frame, then loading + ready redrawn every frame until Space (F12) ..." |
| F13 | First game frame fires with the Space that dismissed "ready" | `jogo.cpp:121,264` | `break` happens before `C2D2_Sincroniza`, so `Space.pressionado` is still set on the first game frame and a shot is fired | The press (Space or left button/tap) that dismissed "ready" is consumed: it does not fire on the first frame nor while it stays held; releasing it (or a new press edge) re-arms firing. Test: "scripted run: ... (F13, F15)" (no player shot for 10 frames while the dismissing Space is held) |
| F14 | `Boss` NULL dereference | `jogo.cpp:163,202,208` | `Marca *Boss = 0` stays NULL when the map has no `M_BOSS` mark (fase6–8, or a missing map) and `Boss->tipo` crashes | `Boss` is an index (−1 = none). Without a boss the phase ends when the map scroll is over (`fase.ymapa <= -600`), as a win if the player is alive (same save/record/reload path), or on death as before. Test: "no boss marker (missing map): no crash, the phase ends (as a win) when the map scroll finishes (F14)" |
| F15 | Esc from the game keeps the aborted run's unlocks | `jogo.cpp:199-200` | Esc only sets `estado_atual = TELA_MISSION`; weapons picked up in the aborted run stay unlocked in RAM (and `planeta_atual` stays) until the next slot load, and are saved by the next win | When the game screen ends after an Esc, `menu_saves_loadslot(slotAtual)` reloads the slot, so RAM matches the stored slot exactly (as after a death). Test: "scripted run: ... (F13, F15)" (`saveAtual` equals the stored slot after Esc) |
| F17 | Pixel-collision engine word-combining bugs | `chien2d2.cpp:1020-1051` (`C2D2_SobrepoeBitMasks`; also `:1035`) | When combining 32-pixel mask words the engine sign-extends a signed `int` (`temp >> (32-bit)`: false positives when the next word starts solid), reuses mask B's first word for overlaps of 64 px or more (bomb / TIRO5 vs bosses), and reads past the row end | A clean per-pixel AND of the two masks over the overlap rectangle, after the same bounding-box reject (`web/src/engine/collision.ts`, implemented in Task 5; logged here per Ruling R8). Tests: `tests/unit/collision.test.ts` |
| D10 (web addition) | Volume options persist across sessions | `funcoes_M.cpp:10`, `menu.cpp:443-532`; `01-game-spec §8` | `volume_music`/`volume_effects` reset to 30/30 on every launch; never saved | Restored from localStorage in `menu_carrega` (then `CA2_AjustaVolume`), saved by `menu_opcoes` on any frame where a volume changed |
| R11/R12 (web addition) | Pause / audio unlock | — | No pause in the original | Tab hidden or window blur during TELA_JOGO shows a pause overlay, freezes the logic (no catch-up) and pauses the music (`CA2_PausaMusica`/`CA2_ContinuaMusica`, chienaudio2.cpp:495,504); any key / click / tap resumes and is not passed to the game. Music is also paused while the tab is hidden in the menus. Audio is (re)unlocked on every pointerdown / keydown / touchend |
| D10 (web addition) | Touch controls + OS-keyboard name entry | `funcoes_J.cpp:40-55` (keyboard target step), `funcoes_M.cpp:39-62` (`XDesenhaBotao`), `menu.cpp:646-700` (name entry); spec §5.3–5.4 | Keyboard/mouse only; names typed on a physical keyboard | `web/src/touch/touch.ts`, shown only on `pointer: coarse` devices or after the first touch. Menus: a tap is a left click with the cursor hotspot (8,6) placed on the finger. Game: a relative drag moves the ship target via `moveAlvoToque` (CSS px → logical px; the ship keeps its original chase easing), clamped to the keyboard's own target range [1, 829] × [1, 629], while the finger holds Space; BOMBA = Left Ctrl, ARMA = Left Alt, ⏸ = confirmation "Voltar ao menu?" (logic frozen while open) → Esc. Quick taps whose down/up land in one frame keep their press edge (the up is delivered one poll later). Name entry focuses the hidden `#texto` on the next tap (OS keyboard); its edits reach the game as typed characters and Backspace key presses (one per frame, in order). Layout: portrait canvas on top + 260 px control panel; landscape side bars (≥ 96 px) or 40 %-opacity corner buttons; safe-area aware. PWA manifest + icons. Tests: `tests/unit/touch.test.ts` |
